# Меч Кейна: защита состояния при конфедерации

Штатный обработчик конфедерации может записать фракцию святыни в кеш владельца меча, после чего `correct_script_cache` сбрасывает стадию до первой. Это приводит к появлению нового меча первой стадии при оставшемся в инвентаре мече второй стадии и штрафах второй стадии.

Этот небольшой скрипт оборачивает только `sword_of_khaine:correct_script_cache`: определяет стадию по настоящему предмету персонажа и сохраняет таймер, если персонаж и стадия не изменились. Законная смена владельца, возвращение в святыню, дилеммы и другие штатные обработчики сохранены. Скрипт не выдаёт предметы и не повышает стадию. Уже повреждённое сохранение требует отдельного исправления.

```text
node khaine-confederation-fix/build.mjs [папка_data_игры]
python khaine-confederation-fix/test_guard.py
```

Тесты требуют Lupa с Lua 5.1 (`TWW3_LUPA_PATH` для локальной установки). Сборщик извлекает актуальный штатный скрипт в игнорируемый `.build-cache`, чтобы тест прогонял реальный обработчик конфедерации. Девять сценариев проверяют воспроизведение сбоя без защиты, сохранение стадии/таймера с защитой, настоящую смену владельца и нормальную дилемму.

Результат `khaine_confederation_fix.pack` имеет тип Movie и загружается автоматически из `data` после полного перезапуска игры. Для отключения убрать этот файл из `data`; галочка менеджера не отключает Movie-пакет. Сохранять скрипт после ремонта сейва полезно для защиты от повторения. [Формат и порядок типов пакетов](https://docs.rs/tw_pack_lib/latest/tw_pack_lib/enum.PFHFileType.html).
